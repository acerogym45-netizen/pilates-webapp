관리자 로그인 및 권한 체계
관리자 접속 주소, 로그인 방법, 권한 구분
3-1. 관리자 종류
🔴 마스터 관리자
  • 비밀번호: 환경변수 MASTER_PASSWORD
  • 모든 단지 데이터 열람·수정 가능
  • 단지 추가·삭제 가능
  • 단지 선택 후 해당 단지 데이터 관리 가능

🔵 단지 관리자
  • 비밀번호: DB complexes.admin_password
  • 본인 단지 데이터만 열람·수정 가능
  • 로그인 시 단지 코드 + 비밀번호 입력 필요
  • 단지 추가·삭제 불가

3-3. 단지 관리자 비밀번호 변경 방법

단지 관리자 비밀번호는 Supabase 대시보드에서 직접 변경합니다.

-- Supabase SQL 에디터에서 실행 UPDATE complexes SET admin_password = '새비밀번호' WHERE code = '단지코드';
마스터 비밀번호 변경은 Vercel 대시보드 → Settings → Environment Variables → MASTER_PASSWORD 수정 후 재배포해야 합니다.
CHAPTER 04
입주민 워크플로우 — 전자계약서 및 수강신청
입주민이 QR 스캔부터 수강신청 완료까지의 전 과정
4-1. QR코드 접속 → 전자계약서 작성 흐름

각 단지마다 고유 QR코드가 부여됩니다. QR코드는 아래 URL 형식입니다:

https://apt-webapp.vercel.app/?complex=[단지코드]
Step 1 — QR 스캔
입주민이 피트니스센터 비치된 QR코드 스캔 → 브라우저에서 시스템 접속. /?complex=코드 파라미터로 단지 자동 인식.
Step 2 — 프로그램 선택
활성화된 프로그램 목록 표시 (is_active=true인 것만). 접수 기간(매월 22~26일)에만 신규 선택 가능. 프로그램 선택 후 희망 시간대·요일 선택.
Step 3 — 개인정보 입력
동, 호수, 이름, 전화번호 입력. 전화번호는 중복 신청 방지 및 내 신청 조회에 사용됨.
Step 4 — 전자계약서 동의
해지 및 환불 규정 필독·동의 체크박스. 이용약관 ①~⑧ 동의 체크박스. 모두 체크해야 다음 단계 진행 가능.
Step 5 — 전자서명 및 제출
성명 입력 + 서명 패드에 직접 서명. 제출 시 POST /api/applications 호출 → DB 저장.
4-2. 수강 신청 처리 로직 (자동승인 / 대기)

신청 제출 후 서버에서 다음 로직으로 자동 처리됩니다:

정원 확인 로직:
해당 프로그램·시간대의 status='approved' 건수 조회 → 정원(capacity) 미만이면 즉시 approved, 초과면 waiting + 대기순번 자동 부여.
신청 제출
→
중복 신청 체크동일 프로그램+시간대
→
정원 확인approved 카운트
→
정원 미만
→ approved
→
정원 초과
→ waiting + 순번
대기자 처리: 승인자가 해지하면 waiting 상태의 최우선순위(waiting_order=1) 입주민이 자동으로 approved 전환되지 않습니다. 관리자가 수동으로 상태를 변경해야 합니다.
중복 신청 방지
동일 단지 + 동일 프로그램 + 동일 시간대에 이미 approved 또는 waiting 신청이 있으면 재신청 차단.
접수 기간 외 차단
매월 22일 09:00 ~ 26일 09:00 외 기간에는 프로그램 is_active=false로 자동 설정되어 신청 버튼 자체가 비활성화됨.
4-3. 내 신청 조회 · 취소 · 변경

입주민은 별도 로그인 없이 동 + 호수 + 전화번호 뒤 4자리로 본인 신청 내역을 조회할 수 있습니다.

기능가능 기간처리 방식
내 신청 조회상시동·호수·전화번호 4자리로 마스킹된 목록 표시
신청 취소매월 22일 09시 ~ 26일 09시해당 application status → cancelled
신청 변경매월 22일 09시 ~ 26일 09시취소 후 재신청 (직접 재신청 필요)
접수 기간 외에는 취소·변경 버튼이 잠금 처리됩니다. 부득이한 경우 관리자에게 직접 요청해야 합니다.

const nowKst = new Date(new Date().getTime() + 9 * 60 * 60 * 1000); const dayKst = nowKst.getUTCDate(); const hourKst = nowKst.getUTCHours(); const isInPeriod = (dayKst === 22 && hourKst >= 9) || // 22일 09시 이후 (dayKst > 22 && dayKst < 26) || // 23·24·25일 전체 (dayKst === 26 && hourKst < 9); // 26일 09시 미만
이 로직은 서버(misc.js), 클라이언트(main.js), 관리자(cancellations.js), Cron(cron.js) 4곳에 동일하게 적용됩니다.

6-1. 입주민 해지 신청 흐름
Step 1 — 접수 기간 확인
입주민 화면 하단 "내 신청 관리" 탭 진입. 매월 22일 09:00 ~ 26일 09:00 기간에만 해지 신청 버튼 활성화. 기간 외에는 잠금 아이콘과 다음 기간 안내 표시.
Step 2 — 수강 프로그램 조회
동 + 호수 + 전화번호 입력 → GET /api/cancellations/lookup-programs 호출 → 현재 approved 상태의 수강 프로그램 목록 표시. 전화번호 불일치 시 끝 4자리 매칭 시도 + 힌트 표시.
Step 3 — 해지할 프로그램 선택
목록에서 해지를 원하는 수강 건 선택. 이미 해지 신청된 건은 목록에서 제외됨 (중복 해지 방지).
Step 4 — 필독 동의 및 제출
번복 불가 안내, 익월 해지 적용 안내 필독 동의 후 제출. POST /api/cancellations 호출.
Step 5 — 즉시 자동 승인 완료
서버에서 즉시 status='approved' + processed_at 자동 설정. 연결된 applications 행도 status='cancelled'로 자동 전환. 관리자 개입 없이 완전 자동 처리.
⚠ 해지는 번복이 절대 불가합니다
입주민이 제출한 해지 신청은 즉시 처리되며 취소할 수 없습니다. 이 점을 입주민에게 반드시 고지하세요. 잘못 제출된 경우 관리자가 DB를 직접 수정해야 합니다.

API 전체 500 에러 Supabase 연결 실패 (환경변수 오류) Vercel 대시보드 → Environment Variables 확인. SUPABASE_URL, SUPABASE_ANON_KEY 재확인 후 재배포.
접수 기간인데 신청 불가 Cron 미실행 → is_active=false 유지 관리자 프로그램 탭 → [즉시 활성화] 버튼으로 수동 처리. Vercel 플랜 확인 (Cron은 Pro 이상).
해지 신청 기간 외라고 에러 서버 KST 기간 체크 통과 실패 현재 날짜/시간 확인. 22일 09:00 ~ 26일 09:00 범위 재확인. 관리자 직접 등록으로 대응.
정산 엑셀 다운로드 안 됨 데이터 없거나 조회 오류 조회월이 올바른지 확인. F12 개발자도구 → 콘솔 에러 확인. 새로고침 후 재시도.
관리자 로그인 불가 비밀번호 오류 또는 단지 코드 오류 마스터: MASTER_PASSWORD 환경변수 확인. 단지 관리자: Supabase DB complexes.admin_password 확인.
SMS 발송 안 됨 Solapi 설정 미완료 SOLAPI_API_KEY, SOLAPI_API_SECRET, SOLAPI_SENDER 환경변수 설정. 관리자 설정 탭에서 테스트 발송.
입주민 화면 흰 화면 JS 오류 또는 단지코드 없는 접속 URL에 ?complex=코드 파라미터 있는지 확인. F12 콘솔 에러 확인.
서명 저장 실패 파일 업로드 서버 오류 Vercel 서버리스 /tmp 용량 한계. 서명 이미지 압축 후 재시도.
9-2. 긴급 상황 대응 절차
DB 데이터 직접 수정이 필요한 경우
Supabase 대시보드 → 프로젝트 → Table Editor 또는 SQL Editor에서 직접 조회/수정 가능합니다.
반드시 WHERE 조건을 정확히 확인한 후 UPDATE/DELETE 실행하세요. 잘못된 쿼리는 전체 데이터에 영향을 줄 수 있습니다.
-- 해지 신청 취소 (긴급 시 DB 직접 수정) UPDATE cancellations SET status = 'rejected' WHERE id = '해지신청-UUID'; UPDATE applications SET status = 'approved' WHERE id = '수강신청-UUID'; -- 특정 신청 상태 변경 UPDATE applications SET status = 'approved' WHERE id = 'UUID'; -- 프로그램 수동 활성화 UPDATE programs SET is_active = true WHERE complex_id = '단지-UUID';
9-3. Vercel 배포 로그 확인

Vercel 대시보드 → 프로젝트 → Deployments → 최신 배포 선택 → Functions 탭에서 서버리스 함수 실행 로그 확인 가능합니다. Cron Job 실행 결과도 여기서 확인합니다.

Cron 실행 로그는 Vercel 대시보드 → Logs 탭에서 /api/cron으로 필터링하면 확인할 수 있습니다.

10-2. 코드 수정 → 배포 절차
# 1. 코드 수정 후 변경 확인 git status # 2. 스테이징 git add . # 3. 커밋 git commit -m "fix: 수정 내용 설명" # 4. Vercel 프로덕션 배포 npx vercel --prod --yes # 5. 배포 완료 후 URL 확인 # https://apt-webapp.vercel.app 에서 동작 검증
배포 전 반드시 확인:
  • JS 문법 오류: node --check [파일명]으로 사전 검증
  • API 라우트 순서: 구체적 경로(/schedule-status)가 동적 경로(/:id)보다 앞에 위치해야 함
  • 환경변수: 새 환경변수 추가 시 Vercel 대시보드에서 먼저 등록 후 배포
10-3. 새 단지 추가 방법
Step 1 — 마스터 관리자 로그인
단지 코드 없이 MASTER_PASSWORD만 입력하여 로그인.
Step 2 — 단지 관리 탭 → [단지 추가]
단지명, 코드(영문 소문자), 주소, 관리자 비밀번호 입력. 코드는 QR URL에 사용되므로 간결하게 설정.
Step 3 — 프로그램 추가
프로그램 관리 탭에서 새 단지 선택 후 프로그램 추가.
Step 4 — QR코드 생성 및 배포
대시보드 → 입주민 바로가기 패널에서 QR 이미지 생성. 출력하여 센터에 비치.
